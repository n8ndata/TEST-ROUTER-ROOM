# คู่มือติดตั้ง Google Sheets + Apps Script

คู่มือนี้พาเริ่มจากศูนย์จนได้ Web App URL ที่นำไปวางในหน้าเว็บ ROUTER
ระบบจะใช้ Google Sheets เป็นฐานข้อมูลกลาง และใช้ Apps Script เป็น API

> ใช้ไฟล์ [`google-apps-script/Code.gs`](google-apps-script/Code.gs) เท่านั้น
> ไม่ต้องติดตั้งไลบรารีเพิ่ม

---

## 1. สิ่งที่ต้องมี

- บัญชี Google ที่สร้าง Google Sheets ได้
- สิทธิ์แก้ไขไฟล์ Sheets (เจ้าของหรือผู้ที่ได้รับสิทธิ์)
- เบราว์เซอร์เดสก์ท็อปสำหรับทำขั้นตอน Deploy (แนะนำ Chrome)
- ไฟล์ `Code.gs` จากโปรเจกต์นี้

---

## 2. สร้างสเปรดชีต

1. เปิด [Google Sheets](https://sheets.google.com) แล้วสร้างสเปรดชีตใหม่
2. ตั้งชื่อไฟล์ เช่น `ROUTER Error Tracking`
3. ไม่จำเป็นต้องสร้างชีตย่อยเอง เพราะสคริปต์จะสร้างให้
4. เก็บลิงก์ไฟล์ไว้ เผื่อต้องกลับมาแก้ไข

> สคริปต์ต้องผูกกับไฟล์ Sheets นี้ เพราะใช้ `SpreadsheetApp.getActiveSpreadsheet()`
> หากสร้างสคริปต์แบบ standalone จะหาไฟล์ไม่เจอ

---

## 3. เปิด Apps Script และวางโค้ด

1. ในไฟล์ Sheets ไปที่ **ส่วนขยาย (Extensions) → Apps Script**
2. ลบโค้ดเดิมใน `Code.gs` ให้หมด
3. เปิดไฟล์ `google-apps-script/Code.gs` จากโปรเจกต์นี้
4. คัดลอกทั้งหมดไปวาง
5. กด **บันทึก** (Ctrl/Cmd + S)
6. ตั้งชื่อโปรเจกต์ เช่น `ROUTER API`

หลังวางโค้ด ควรเห็นฟังก์ชันหลัก เช่น `setupSystem`, `doGet`, `doPost`

---

## 4. รัน setupSystem ครั้งแรก

1. ในหน้า Apps Script เลือกฟังก์ชัน **`setupSystem`** จาก dropdown ด้านบน
2. กด **Run**
3. ครั้งแรก Google จะขออนุญาตสิทธิ์:
   - เลือกบัญชีที่ต้องการ
   - กด **Advanced / Advanced access** ถ้ามีคำเตือน
   - กด **Go to ROUTER API (unsafe)** เฉพาะกรณีที่เป็นสคริปต์ของคุณเอง
   - กด **Allow**
4. กลับไปดูไฟล์ Sheets จะพบชีตใหม่ 2 ชีต

### ชีตที่ถูกสร้าง

#### `รายชื่อพนักงาน`
หัวคอลัมน์ (แถว 1):

| คอลัมน์ | หัวข้อ | ตัวอย่าง |
|---|---|---|
| A | รหัสพนักงาน | `RT001` |
| B | ชื่อ-นามสกุล | `สมชาย ใจดี` |
| C | แผนก | `ROUTER` |
| D | กะประจำ | `กะเช้า` |
| E | ตำแหน่ง | `หัวหน้ากะ` |
| F | เบอร์โทร | `081-234-5678` |
| G | สถานะ | `ใช้งาน` |

- ถ้าคอลัมน์ G ว่าง → ถือว่า **ใช้งาน**
- ค่าที่ถือว่าปิดใช้งาน: `ไม่ใช้งาน`, `ลาออก`, `inactive`, `false`, `0`, `no`, `leave`, `resigned` (ไม่สนตัวพิมพ์เล็ก/ใหญ่)
- พนักงานที่ปิดใช้งานจะไม่ปรากฏใน dropdown บันทึก และปุ่มบันทึกในการ์ดจะถูกปิด
- ถ้าไม่มีแถวพนักงานที่ใช้งานอยู่ หน้าเว็บจะปิดช่องเลือกพนักงาน พร้อมแจ้งให้ตรวจสอบชีต

#### `บันทึกความผิดพลาด`
หัวคอลัมน์ (แถว 1) เรียงตามนี้:

| # | หัวข้อ | ความหมาย |
|---|---|---|
| A | `ID` | รหัสรายการ เช่น `ERR-261026-153045-A7F3` (วันที่ + เวลา + random) |
| B | `วันที่บันทึก` | timestamp ตอนสร้าง |
| C | `วันที่เกิดเหตุ` | `yyyy-MM-dd` |
| D | `กะ` | กะเช้า / กะบ่าย / กะดึก / กะปกติ |
| E | `รหัสพนักงาน` | รหัสจากชีตพนักงาน |
| F | `ชื่อพนักงาน` | ชื่อ ณ เวลาบันทึก |
| G | `เครื่องจักร` | เช่น `Router-01 (CNC Precision)` |
| H | `Part No.` | ชื่องาน/โมเดล |
| I | `ประเภทความผิดพลาด` | ข้อความอิสระ |
| J | `ระดับความรุนแรง` | เล็กน้อย / ปานกลาง / สูง / วิกฤต |
| K | `รายละเอียด` | รายละเอียดเหตุการณ์ |
| L | `ผลกระทบ/ของเสีย` | จำนวนชิ้น/นาที/บาท |
| M | `ผู้บันทึก` | ชื่อหัวหน้ากะ/ช่าง |
| N | `สาเหตุเบื้องต้น` | Root cause |
| O | `แนวทางแก้ไข` | Corrective action |
| P | `สถานะ` | รอดำเนินการ / กำลังตรวจสอบ / อบรมซ้ำแล้ว / ปิดงาน |
| Q | `หมายเหตุ` | หมายเหตุเพิ่มเติม |
| R | `อัปเดตล่าสุด` | timestamp ที่แก้ไขล่าสุด |
| S | `ผู้แก้ไขล่าสุด` | ชื่อผู้แก้ไข |

> ห้ามสลับลำดับคอลัมน์ เพราะ API อ่าน/เขียนตามตำแหน่งคอลัมน์
> หากต้องการเพิ่มคอลัมน์ ให้ต่อท้ายและแก้โค้ดทั้งฝั่ง GAS และ frontend

สคริปต์จะใส่ข้อมูลพนักงานตัวอย่าง 12 คน และรายการตัวอย่างให้อัตโนมัติ
เมื่อชีตยังว่าง เพื่อให้ทดสอบได้ทันที

## 5. Deploy เป็น Web App

1. ที่มุมขวาบนของ Apps Script กด **Deploy → New deployment**
2. กดไอคอนเฟือง เลือก **Web app**
3. ตั้งค่า:

| ช่อง | ค่า |
|---|---|
| Description | `ROUTER API v1` |
| Execute as | **Me (บัญชีของคุณ)** |
| Who has access | **Anyone** |

4. กด **Deploy**
5. อนุญาตสิทธิ์อีกครั้งหากระบบขอ
6. คัดลอก **Web app URL** ที่ลงท้ายด้วย `/exec`

ตัวอย่าง URL:

```text
https://script.google.com/macros/s/AKfycb.../exec
```

### ทำไมต้องเป็น Anyone
หน้าเว็บเรียก API จากเบราว์เซอร์โดยไม่มีระบบ login ของ Google
ถ้าเลือก “Anyone with Google account” หรือจำกัดสิทธิ์ จะเรียกไม่ได้
หรือถูก redirect ไปหน้า login และหน้าเว็บจะอ่าน JSON ไม่ได้

> ความปลอดภัย: ใครมี URL นี้สามารถอ่าน/เขียนข้อมูลได้
> ควรเก็บ URL เป็นความลับภายในทีม และเปลี่ยน deployment ใหม่หาก URL รั่ว

---

## 6. ตั้งค่าในหน้าเว็บ

1. เปิดหน้าเว็บ ROUTER
2. กดไอคอนเฟือง (ตั้งค่าการเชื่อมต่อ)
3. วาง URL ที่ลงท้าย `/exec`
4. กด **บันทึกและซิงค์ทันที**
5. ควรเห็นข้อความ:

```text
เชื่อมต่อสำเร็จ! ดึงพนักงาน 12 คน และรายการ 5 รายการ
```

(ตัวเลขรายการขึ้นกับข้อมูลจริงในชีต; ตัวอย่างเริ่มต้นของ Apps Script มี 5 รายการ)

6. แถบสถานะ header เปลี่ยนเป็น **ออนไลน์**

ถ้าเชื่อมต่อไม่สำเร็จ ให้ดูข้อความ error และตรวจ Troubleshooting ด้านล่าง

## 7. ทดสอบ API ด้วยตัวเอง

### เปิดในเบราว์เซอร์
วาง URL นี้ในเบราว์เซอร์ (แทน `<URL>`):

```text
<URL>?action=ping
```

ควรได้ JSON:

```json
{"ok":true,"pong":true,"timestamp":"2026-10-26T10:00:00.000Z","spreadsheet":"ROUTER Error Tracking"}
```

### ดูข้อมูลทั้งหมด

```text
<URL>?action=all
```

โครงสร้าง:

```json
{
  "ok": true,
  "employees": [
    {
      "id": "RT001",
      "code": "RT001",
      "name": "สมชาย ใจดี",
      "department": "ROUTER",
      "shift": "กะเช้า",
      "position": "หัวหน้ากะ",
      "phone": "081-234-5678",
      "active": true
    }
  ],
  "incidents": [],
  "timestamp": "2026-10-26T10:00:00.000Z"
}
```

### ทดสอบด้วย curl

อ่านข้อมูล:

```bash
curl -L "https://script.google.com/macros/s/XXXX/exec?action=ping"
```

สร้างรายการ (POST เป็น `text/plain` เพื่อเลี่ยง CORS preflight):

```bash
curl -L -X POST \
  -H "Content-Type: text/plain;charset=utf-8" \
  --data '{
    "action": "createIncident",
    "data": {
      "employeeId": "RT001",
      "employeeName": "สมชาย ใจดี",
      "date": "2026-10-26",
      "shift": "กะเช้า",
      "machine": "Router-01 (CNC Precision)",
      "category": "ทดสอบระบบ",
      "severity": "ปานกลาง",
      "description": "ทดสอบการเชื่อมต่อจาก curl",
      "reporter": "tester"
    }
  }' \
  "https://script.google.com/macros/s/XXXX/exec"
```

> ควรลบรายการทดสอบออกจากชีตภายหลัง

## 8. API actions ที่รองรับ

### GET

| action | ผลลัพธ์ |
|---|---|
| `all` (ค่าเริ่มต้น) | employees + incidents |
| `ping` | ตรวจการเชื่อมต่อ |
| `employees` | รายชื่อพนักงาน |
| `incidents` | รายการข้อผิดพลาด |

### POST

ส่ง JSON body โดยมี `action` และข้อมูลที่เกี่ยวข้อง

#### `createIncident`

```json
{
  "action": "createIncident",
  "data": {
    "id": "ERR-261026-153045-A7F3",
    "employeeId": "RT001",
    "employeeName": "สมชาย ใจดี",
    "date": "2026-10-26",
    "shift": "กะเช้า",
    "machine": "Router-01 (CNC Precision)",
    "partNo": "PCB-MB-8802",
    "category": "ตั้งค่าโปรแกรม / G-Code ผิดพลาด",
    "severity": "สูง",
    "description": "รายละเอียดเหตุการณ์",
    "impact": "เสียหาย 3 ชิ้น",
    "reporter": "หัวหน้ากะ",
    "rootCause": "สาเหตุเบื้องต้น",
    "corrective": "แนวทางแก้ไข",
    "updatedBy": "web-app"
  }
}
```

- ถ้าส่ง `id` ที่มีอยู่แล้ว จะคืนรายการเดิมและ `duplicate: true`
  (กันการสร้างซ้ำเมื่อ request timeout แล้ว retry)
- ถ้าไม่ส่ง `id` ระบบจะสร้างรหัสให้

#### `updateIncident`

```json
{
  "action": "updateIncident",
  "id": "ERR-261026-153045-A7F3",
  "data": {
    "status": "กำลังตรวจสอบ",
    "rootCause": "สาเหตุที่แท้จริง",
    "corrective": "แนวทางแก้ไข",
    "notes": "หมายเหตุ",
    "updatedBy": "หัวหน้ากะ"
  }
}
```

ฟิลด์ที่แก้ได้: `status`, `description`, `rootCause`, `corrective`, `notes`,
`severity`, `shift`, `category`, `impact`, `partNo`, `machine`

ถ้าไม่พบ ID ที่จะแก้ (เช่น แถวถูกลบในชีตระหว่างที่เครื่องนั้นออฟไลน์)
ระบบจะคืน `ok: true, missing: true` เพื่อให้คิวฝั่งเบราว์เซอร์ล้างรายการนั้นได้
และไม่ไปบล็อกรายการอื่นที่รอซิงค์อยู่

#### `deleteIncident`

```json
{
  "action": "deleteIncident",
  "id": "ERR-261026-153045-A7F3"
}
```

ถ้าไม่พบรายการ จะคืน `ok: true, deleted: false` เพื่อให้การลบซ้ำไม่ทำให้คิวค้าง

### รูปแบบ error

```json
{
  "ok": false,
  "error": "ข้อความอธิบาย"
}
```

หน้าเว็บจะอ่าน `error` และแสดงในแถบสถานะ/ทอสต์

## 9. การอัปเดตโค้ดหลังแก้ไข

หลังแก้ `Code.gs` ต้องสร้าง version ใหม่:

1. **Deploy → Manage deployments**
2. กดไอคอนดินสอที่ deployment ที่ใช้งาน
3. ช่อง Version เลือก **New version**
4. กด **Deploy**
5. URL เดิมยังใช้ได้ (ไม่ต้องเปลี่ยนในหน้าเว็บ)

ถ้าแก้เพียงตัวแปร `CONFIG` เช่น timezone หรือชื่อชีต ให้ deploy version ใหม่เช่นกัน

---

## 10. Timezone และวันที่

- ค่าเริ่มต้นใช้ timezone ของไฟล์ Apps Script
  (ปกติคือ `Asia/Bangkok` สำหรับบัญชีไทย)
- ตรวจ/แก้ได้ที่ **Project Settings → Time zone**
- วันที่ในชีตถูก normalize เป็น `yyyy-MM-dd`
- รองรับวันที่แบบ:
  - `2026-10-26`
  - `26/10/2026`
  - `26.10.2569` (พ.ศ. จะถูกแปลงเป็น ค.ศ.)
  - วันที่ที่ Google Sheets ส่งมาเป็น object `Date`

## 11. ความปลอดภัย

- Web App แบบ **Anyone** ไม่มี authentication
  ใครมี URL สามารถเรียก API ได้
- ไม่ควรใส่ข้อมูลส่วนบุคคลอ่อนไหวเกินจำเป็น
- ควรจำกัดสิทธิ์แก้ไขไฟล์ Sheets ให้เฉพาะทีมที่เกี่ยวข้อง
- ถ้า URL รั่ว:
  1. สร้าง deployment ใหม่
  2. อัปเดต URL ในหน้าเว็บทุกเครื่อง
  3. ลบ deployment เก่า
- Apps Script มี quota ตามบัญชี Google (โดยทั่วไปเพียงพอสำหรับทีมขนาดเล็ก)
- ระบบใช้ `LockService` ล็อกการเขียน 20 วินาที เพื่อลดการเขียนชนกัน

## 12. Troubleshooting

### หน้าเว็บขึ้น “URL นี้ไม่ใช่ Web App API”
- Deploy ยังไม่เสร็จ หรือ URL เป็นลิงก์ `/edit` ไม่ใช่ `/exec`
- สิทธิ์เข้าถึงไม่ใช่ **Anyone**
- เปิด URL ในเบราว์เซอร์แล้วเจอหน้า login หรือ HTML

### ขึ้น “เชื่อมต่อเซิร์ฟเวอร์ไม่ได้”
- ตรวจอินเทอร์เน็ต
- ตรวจว่า URL ยังใช้งานได้ (เปิด `?action=ping`)
- ถ้าเพิ่ง deploy อาจใช้เวลาสักครู่
- เบราว์เซอร์บางตัวบล็อก third-party cookie แต่ API นี้ไม่ใช้ cookie

### ขึ้น “ไม่พบ Google Sheets ที่ผูกกับสคริปต์”
- สคริปต์ถูกสร้างแบบ standalone ไม่ได้เปิดจาก Sheets
- ให้เปิดไฟล์ Sheets → Extensions → Apps Script แล้ววางโค้ดใหม่

### ขึ้น “ไม่รู้จัก action”
- URL หรือ body ส่ง `action` ผิด
- ถ้าแก้โค้ดเอง ให้ตรวจชื่อ action ใน `doGet`/`doPost`

### ข้อมูลในชีตไม่ขึ้นในหน้าเว็บ
- กดซิงค์ด้วยมือ
- ตรวจชื่อชีตให้ตรงเป๊ะ: `รายชื่อพนักงาน`, `บันทึกความผิดพลาด`
- ตรวจว่าแถวข้อมูลเริ่มแถว 2
- ตรวจว่า ID ไม่ว่าง
- ตรวจว่าไม่มีแถวว่างคั่นกลางจำนวนมาก (อ่านถึงแถวสุดท้าย)

### สร้างรายการแล้วได้ `duplicate: true`
- มี ID นี้อยู่ในชีตแล้ว
- หน้าเว็บใช้ ID เดียวกันเพื่อกันการสร้างซ้ำ
- ถ้าต้องการสร้างใหม่ ให้ตรวจรหัสที่สร้างในเครื่องและลบรายการเก่าออกก่อน

### ซิงค์ช้า/หมดเวลา
- Apps Script อาจใช้เวลาหลายวินาทีเมื่อชีตมีข้อมูลมาก
- หน้าเว็บตั้ง timeout 20 วินาที
- ถ้าชีตใหญ่กว่า ~5,000 แถว ควรแบ่งไฟล์หรือใช้ฐานข้อมูลอื่น
- ระหว่าง timeout รายการจะยังอยู่ในคิวและลองใหม่รอบถัดไป

### วันที่เพี้ยน
- ตรวจ timezone ของ Apps Script
- ตรวจว่ารูปแบบวันที่ในชีตเป็นวันที่จริง ไม่ใช่ข้อความที่ตีความไม่ได้
- หน้าเว็บแสดงผลเป็น พ.ศ. ตาม locale ไทย แต่เก็บค่าจริงเป็น ค.ศ.

## 13. การสำรองและกู้คืนข้อมูล

- ใช้ **File → Make a copy** ใน Google Sheets เพื่อสำรองทั้งไฟล์
- หรือ **File → Download → Microsoft Excel (.xlsx)**
- กู้คืนโดยนำเข้าข้อมูลกลับเข้าชีตตามหัวคอลัมน์เดิม
- ก่อนล้างข้อมูลในหน้าเว็บ ควรส่งออก CSV เก็บไว้ก่อน

## 14. โครงสร้างการทำงานโดยย่อ

```text
เบราว์เซอร์
  ├─ localStorage (ข้อมูล + คิว)
  ├─ GET  <URL>?action=all          → โหลดพนักงานและรายการ
  ├─ GET  <URL>?action=ping         → ทดสอบการเชื่อมต่อ
  ├─ POST <URL> {action:createIncident}
  ├─ POST <URL> {action:updateIncident}
  └─ POST <URL> {action:deleteIncident}
          │
          ▼
Google Apps Script (doGet / doPost)
  ├─ LockService (กันเขียนชนกัน)
  ├─ ตรวจและ normalize ข้อมูล
  ├─ อ่าน/เขียนชีต
  └─ คืน JSON
```

ลำดับการซิงค์ของหน้าเว็บ:

1. ส่ง operation ในคิวตามลำดับที่บันทึกไว้ (create/update/delete)
2. ดึงข้อมูลล่าสุดด้วย `action=all`
3. แทนที่ state ในเครื่องด้วยข้อมูลจากชีต
4. บันทึก cache และแจ้งสถานะออนไลน์

หากขั้นตอนใดล้มเหลวจากเครือข่ายหรือเซิร์ฟเวอร์ คิวจะยังอยู่และลองใหม่ในการซิงค์ครั้งถัดไป
(กรณี update แถวที่ถูกลบไปแล้ว เซิร์ฟเวอร์จะตอบ `missing: true` เพื่อไม่ให้คิวค้าง)


## ข้อควรทราบก่อนใช้งานข้อมูลจริง

PIN Admin ทำงานในฝั่งเบราว์เซอร์เท่านั้น จึงไม่สามารถใช้ป้องกันการเรียก API โดยตรงได้ หากเผยแพร่ Apps Script เป็น `Anyone` API จะเปิดให้ผู้ที่ทราบ URL อ่าน/เขียน/ลบข้อมูลได้ ชุดนี้จึงยังต้องเพิ่มการยืนยันตัวตนฝั่งเซิร์ฟเวอร์หรือจำกัดผู้ใช้ด้วย Google Workspace ก่อนใช้งานจริงในองค์กร

`setupSystem()` รุ่นที่ปรับแล้วจะไม่สร้างข้อมูลตัวอย่างเอง หากต้องการข้อมูลทดลอง ให้ใช้ชีตทดสอบที่ไม่มีข้อมูล แล้วเรียก `seedDemoData()` ด้วยตนเองเท่านั้น
