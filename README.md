# ROUTER Dept – Operational Error Tracking System

เว็บแอปสำหรับบันทึก ติดตาม และวิเคราะห์ข้อผิดพลาดในการปฏิบัติงานของแผนก ROUTER
ออกแบบให้ใช้ได้ทั้งมือถือ แท็บเล็ต และเดสก์ท็อป โดยทำงานแบบ **local-first**
คือบันทึกข้อมูลในเครื่องได้ทันที แม้ยังไม่ได้เชื่อมต่อ Google Sheets หรืออินเทอร์เน็ตจะขาดหาย
แล้วค่อยซิงค์ขึ้นชีตเมื่อกลับมาออนไลน์

> เอกสารติดตั้งฝั่ง Google Sheets / Apps Script อยู่ใน [README-GAS.md](README-GAS.md)

---

## 1. ฟีเจอร์ที่มีในระบบ

### การบันทึกข้อมูล
- ฟอร์มบันทึกข้อผิดพลาดครบถ้วน: พนักงาน, วันที่, กะ, เครื่องจักร, Part No.,
  ประเภทความผิดพลาด, ระดับความรุนแรง, รายละเอียด, ผลกระทบ, ผู้บันทึก,
  สาเหตุเบื้องต้น และแนวทางแก้ไข
- Quick chips สำหรับประเภทความผิดพลาดที่พบบ่อย
- เลือกระดับความรุนแรงแบบปุ่มสัมผัส (เล็กน้อย / ปานกลาง / สูง / วิกฤต)
- ตรวจสอบข้อมูลฝั่งหน้าเว็บ พร้อมข้อความผิดพลาดใต้ช่องกรอก
- ตัวนับตัวอักษรของช่องรายละเอียด (สูงสุด 1,500 ตัวอักษร)
- จำชื่อผู้บันทึกล่าสุด และเลือกกะตามเวลาปัจจุบันให้อัตโนมัติ
- แสดงข้อมูลย่อของพนักงานที่เลือก และเปลี่ยนกะให้ตรงกับพนักงานคนนั้น

### ตารางและตัวกรอง
- ค้นหาจากชื่อ รหัส เครื่องจักร อาการ หรือรายละเอียด
- กรองตามกะ ระดับความรุนแรง และสถานะ
- แบ่งหน้า 10 รายการต่อหน้า
- ส่งออก CSV แบบ UTF-8 (เปิดใน Excel ได้ทันที) ตามผลการกรองปัจจุบัน
- ป้องกัน CSV formula injection
- ตารางเลื่อนแนวนอนได้เฉพาะในกรอบตาราง ไม่ทำให้ทั้งหน้าจอเลื่อน sideways

### แดชบอร์ด
- ตัวเลขสรุป: จำนวนข้อผิดพลาดทั้งหมด, เคสรุนแรง/วิกฤต, รอดำเนินการ,
  พนักงานที่พบข้อผิดพลาดสูงสุด
- กราฟ 4 ตัวจาก Chart.js: สัดส่วนความรุนแรง, ประเภทข้อผิดพลาดยอดนิยม,
  จำนวนแยกตามกะ และแนวโน้ม 7 วัน
- เปลี่ยนธีมแล้วกราฟปรับสีตามอัตโนมัติ
- ถ้าโหลด Chart.js ไม่ได้ จะแสดงข้อความสำรองแทนกราฟโดยไม่ทำให้หน้าพัง

### พนักงาน
- แสดงการ์ดพนักงานพร้อมจำนวนข้อผิดพลาด, งานค้าง และวันที่พบล่าสุด
- กดปุ่มบนการ์ดเพื่อไปบันทึกให้พนักงานคนนั้นทันที
- พนักงานที่ถูกปิดใช้งานในชีตจะแสดงป้าย “ไม่ใช้งาน” และกดบันทึกไม่ได้
- ช่องสถานะในชีตที่เป็นค่าว่างถือว่า **ใช้งาน** (ค่าเริ่มต้นที่ปลอดภัย)
- ถ้าชีตไม่มีรายชื่อพนักงาน ระบบจะล้างรายชื่อเดิม แสดงคำแนะนำในฟอร์ม
  และปิดช่องเลือกพนักงานจนกว่าจะเพิ่มข้อมูลในชีต

### Admin / การจัดการ
- เข้าสู่ระบบผู้ดูแลด้วย PIN 4 หลัก
- PIN เริ่มต้น: **`1234`**
- เปลี่ยน PIN ได้จากหน้า Admin และเก็บเป็น SHA-256 hash เมื่อเบราว์เซอร์รองรับ
  (ถ้าไม่รองรับจะเก็บเป็น `plain:` fallback เฉพาะในเครื่อง)
- ล็อกชั่วคราว 30 วินาทีเมื่อกรอก PIN ผิด 5 ครั้ง
- แก้ไขสถานะ/รายละเอียด/สาเหตุ/แนวทางแก้ไข/หมายเหตุของรายการ
- ลบรายการพร้อมกล่องยืนยัน
- ล้างรายการข้อผิดพลาดและคิวซิงค์ในเครื่อง (ไม่ลบรายชื่อพนักงานหรือการตั้งค่า)
- ออกจากโหมด Admin ได้ทันที

### Google Sheets / Offline
- เชื่อมต่อ Google Apps Script Web App URL
- ตรวจสอบ URL ก่อนบันทึก (ต้องเป็น `https://script.google.com/.../exec` หรือ `/dev`)
- มี offline operation queue: create / update / delete จะถูกเก็บไว้แล้วส่งซ้ำเมื่อออนไลน์
- Service Worker แคชหน้าเว็บและ asset ไว้ ทำให้เปิด/รีเฟรชแอปซ้ำได้แม้ไม่มีเน็ต
  (หลังเคยเปิดออนไลน์อย่างน้อยหนึ่งครั้ง และต้อง host บน HTTPS หรือ localhost)
- รหัสรายการสร้างจากวันที่ + เวลา + random suffix จึงไม่ชนกันเมื่อมีหลายแท็บ/หลายเครื่อง
- สร้างรายการซ้ำไม่ได้ เพราะทั้งฝั่งเว็บและ Apps Script ใช้ `id` เป็นตัวกันซ้ำ
- แคชข้อมูลล่าสุดไว้ใน localStorage เพื่อเปิดใช้งานต่อได้เมื่อเน็ตหลุด
- ซิงค์อัตโนมัติทุก 60 วินาที, เมื่อกลับมาที่แท็บ, เมื่อกลับมาออนไลน์
  และหลังบันทึก/แก้ไข/ลบ
- มีปุ่มซิงค์ด้วยมือที่ header

### ธีมและ UX
- 3 โหมด: อัตโนมัติ (ตามเวลา 06:00–17:59 = สว่าง), สว่าง, มืด
- ธีมไอคอนแยกสีตามส่วน: บันทึกข้อมูล (ฟ้า-ไซแอน), แดชบอร์ด (ม่วง-ชมพู),
  รายการทั้งหมด (เขียว-ทีล), พนักงาน (ส้ม-ชมพู) พร้อมไอคอนประจำหัวข้อ
- อวตารพนักงานมีสีเฉพาะบุคคล (คำนวณจากรหัสพนักงาน) และไอคอนตามตำแหน่ง
  (หัวหน้ากะ/ช่าง/QC/ธุรการ/วิศวกร) ใช้สีเดียวกันทั้งฟอร์ม ตาราง และการ์ดพนักงาน
- จำโหมดที่เลือก และตั้งธีมก่อน paint เพื่อลดอาการจอขาววาบตอนกลางคืน
- รองรับ `prefers-reduced-motion`
- Safe area สำหรับ iPhone (notch / home indicator)
- ปุ่มหลักขั้นต่ำ 44–48px, ช่องกรอก 48px
- ฟอนต์ Prompt และ Chart.js เก็บไว้ในเครื่อง จึงไม่ต้องพึ่ง CDN
- มี focus ring, aria-label, `role="dialog"`, การล็อก focus ใน modal และกด Esc เพื่อปิด

## 3. เริ่มใช้งานแบบเร็ว

### 3.1 เปิดแบบไม่เชื่อมต่อ Google Sheets
ใช้ได้ทันทีโดยไม่ต้องตั้งค่าอะไร ระบบจะใช้ข้อมูลพนักงานตัวอย่าง 12 คน
และรายการตัวอย่าง 8 รายการในเครื่อง

แนะนำให้เปิดผ่าน local web server เพื่อให้พฤติกรรมเหมือนเว็บจริง:

```bash
cd lib
python3 -m http.server 8123
# เปิด http://127.0.0.1:8123/
```

หรือจะเปิดไฟล์ `index.html` โดยตรงก็ได้ในการใช้งานพื้นฐาน
แต่การเปิดผ่าน `http://` หรือ `https://` จะเสถียรกว่าเรื่องที่เก็บข้อมูลและ fetch

### 3.2 เชื่อมต่อ Google Sheets
1. ทำตาม [README-GAS.md](README-GAS.md) เพื่อสร้างชีตและ deploy Web App
2. กดไอคอนเฟือง (ตั้งค่าการเชื่อมต่อ) ที่ header
3. วาง URL ที่ลงท้ายด้วย `/exec`
4. กด **บันทึกและซิงค์ทันที**
5. ตรวจสอบว่าแถบสถานะเปลี่ยนเป็น **ออนไลน์** และมีข้อความยืนยันจำนวนพนักงาน/รายการ

หลังเชื่อมต่อ ข้อมูลจากชีตจะแทนที่ชุดข้อมูลตัวอย่างในเครื่อง
(รายการที่ยังไม่ซิงค์จะถูกส่งขึ้นก่อน แล้วจึงดึงข้อมูลล่าสุดกลับมา)
ถ้าชีต `รายชื่อพนักงาน` ไม่มีข้อมูล หน้าเว็บจะไม่แสดงรายชื่อตัวอย่างค้างไว้
แต่จะปิดช่องเลือกพนักงานและแสดงคำแนะนำให้เพิ่มข้อมูลในชีต

### 3.3 เปลี่ยน PIN Admin
1. กดปุ่ม **Admin** ที่ header
2. กรอก PIN เริ่มต้น `1234`
3. ในหน้า Admin กด **เปลี่ยนรหัส PIN**
4. กรอก PIN ปัจจุบัน, PIN ใหม่ 4 หลัก และยืนยัน
5. หลังเปลี่ยนแล้ว คำใบ้ “ค่าเริ่มต้น: 1234” จะถูกซ่อน

> PIN เป็นการป้องกันการแก้ไขโดยไม่ตั้งใจ ไม่ใช่ระบบยืนยันตัวตนระดับองค์กร
> เพราะรหัสถูกเก็บและตรวจสอบฝั่งเบราว์เซอร์

## 4. วิธีใช้ประจำวัน

### บันทึกเหตุการณ์
1. เปิดแท็บ **บันทึกข้อมูล**
2. เลือกพนักงาน (กะจะเปลี่ยนตามพนักงาน)
3. ตรวจวันที่และกะ
4. เลือกเครื่องจักร กรอก Part No.
5. เลือกประเภทความผิดพลาดจากปุ่มลัด หรือพิมพ์เอง
6. เลือกระดับความรุนแรง
7. อธิบายเหตุการณ์อย่างน้อย 5 ตัวอักษร
8. กรอกผลกระทบ/ผู้บันทึก/สาเหตุ/แนวทางแก้ไขตามที่ทราบ
9. กด **บันทึกข้อมูลข้อผิดพลาด**

### ติดตามและปิดงาน
1. เปิดแท็บ **รายการทั้งหมด**
2. ค้นหาหรือกรอง
3. กดปุ่ม **จัดการ** ท้ายแถว
4. กรอก PIN Admin ครั้งแรก
5. เปลี่ยนสถานะเป็น `กำลังตรวจสอบ` → `อบรมซ้ำแล้ว` → `ปิดงาน`
6. กรอกสาเหตุ/แนวทางแก้ไข/หมายเหตุ แล้วกด **บันทึกการแก้ไข**

### ดูสถิติ
เปิดแท็บ **แดชบอร์ด** ตัวเลขและกราฟจะอัปเดตตามข้อมูลล่าสุด

### ส่งออกข้อมูล
- จากแท็บรายการ: ส่งออกตามตัวกรองปัจจุบัน
- จากหน้า Admin: ส่งออกทั้งหมด
- ไฟล์เป็น CSV UTF-8 มี BOM จึงเปิดภาษาไทยใน Excel ได้

## 5. การทำงานออฟไลน์

ระบบใช้กลไก 2 ชั้น:

1. **Local data** – ข้อมูลพนักงานและรายการถูกเก็บใน `localStorage`
   หน้าเว็บจึงยังแสดงข้อมูลเดิมได้เมื่อเน็ตหลุด
2. **Pending queue** – เมื่อสร้าง/แก้ไข/ลบ ระบบจะเก็บ operation ไว้ในคิว
   `router_pending_ops_v1` แล้วส่งขึ้น Google Sheets ตามลำดับเมื่อเชื่อมต่อได้

คิวทำงานตั้งแต่ยังไม่ได้ตั้งค่า GAS URL ด้วย (โหมดในเครื่อง) เพื่อไม่ให้รายการที่
บันทึกก่อนเชื่อมต่อหายไป เมื่อใส่ URL และกด **บันทึกและซิงค์ทันที** ระบบจะส่ง
รายการที่ค้างในคิวก่อน แล้วจึงดึงข้อมูลล่าสุดจากชีตกลับมา รายการที่เพิ่งสร้างจะ
ยังปรากฏในหน้าเว็บและไม่ถูกข้อมูลจากชีตทับ

ข้อยกเว้น: ข้อมูลตัวอย่าง `ERR-MOCK-*` ใช้เพื่อสาธิตในโหมดในเครื่องเท่านั้น
การแก้ไข/ลบข้อมูลตัวอย่างจะไม่ถูกส่งขึ้นชีต และจะไม่ทำให้การซิงค์ครั้งแรกค้าง

สถานะที่ header:

| สถานะ | ความหมาย |
|---|---|
| โหมดในเครื่อง | ยังไม่ได้ตั้งค่า GAS URL |
| กำลังซิงค์... | กำลังส่งคิว/ดึงข้อมูล |
| ออนไลน์ | เชื่อมต่อและซิงค์ล่าสุดสำเร็จ |
| ออฟไลน์ | เชื่อมต่อไม่ได้ ใช้ข้อมูลในเครื่องและเก็บคิวไว้ |

หมายเหตุ: หน้าเว็บลงทะเบียน Service Worker (`sw.js`) เพื่อแคช app shell และ asset
เมื่อเปิดผ่าน HTTPS หรือ localhost หลังโหลดออนไลน์สำเร็จอย่างน้อยหนึ่งครั้ง
จึงสามารถปิดแล้วเปิด/รีเฟรชแอปซ้ำขณะไม่มีเน็ตได้ และยังบันทึกข้อมูลลงคิวในเครื่องได้
ส่วนการเชื่อมต่อ Google Sheets ยังต้องใช้อินเทอร์เน็ตตามปกติ

ถ้าเปิดจาก `file://` เบราว์เซอร์จะไม่รองรับ Service Worker แต่แอปยังใช้งานพื้นฐานได้
โดยไม่มีการแคชหน้าเว็บสำหรับการรีเฟรชแบบออฟไลน์
หากต้องติดตั้งเป็นแอปบนมือถือ แนะนำ host บน HTTPS แล้วใช้เมนู “เพิ่มไปยังหน้าจอโฮม”
ของเบราว์เซอร์

|---|---|
| `router_gas_url` | URL ของ Apps Script Web App |
| `router_api_cache_v1` | แคชข้อมูลล่าสุดจาก Google Sheets |
| `router_employees_v1` | รายชื่อพนักงานในเครื่อง |
| `router_incidents_v1` | รายการข้อผิดพลาดในเครื่อง |
| `router_pending_ops_v1` | คิว create/update/delete ที่ยังไม่ซิงค์ |
| `router_seeded_v1` | ธงว่าเคย seed ข้อมูลตัวอย่างแล้ว |
| `router_theme_mode` | โหมดธีม `auto` / `light` / `dark` |
| `router_last_reporter` | ชื่อผู้บันทึกล่าสุด |
| `router_admin_pin_hash` | PIN hash (หรือ `plain:` fallback) |
| `router_pin_changed` | ธงว่าผู้ใช้เคยเปลี่ยน PIN แล้ว |
| `router_admin_session` | สถานะ Admin ของแท็บนี้ (sessionStorage) |

### ลืม PIN ทำอย่างไร
PIN ไม่ได้ถูกส่งขึ้นเซิร์ฟเวอร์ จึงไม่มีปุ่ม “ลืมรหัส” ฝั่งเซิร์ฟเวอร์
ผู้ที่มีสิทธิ์เข้าถึงเครื่องสามารถรีเซ็ตกลับเป็น `1234` ได้โดยเปิด DevTools
แล้วรัน:

```js
localStorage.removeItem('router_admin_pin_hash');
localStorage.removeItem('router_pin_changed');
location.reload();
```

### ล้างข้อมูลทั้งหมดของแอป
ใช้เมนู **Admin → ล้างข้อมูลในเครื่อง** สำหรับล้างรายการและคิว
ถ้าต้องการล้างทุกอย่างรวมถึง URL และ PIN ให้รัน:

```js
Object.keys(localStorage)
  .filter(function (key) { return key.indexOf('router_') === 0; })
  .forEach(function (key) { localStorage.removeItem(key); });
sessionStorage.removeItem('router_admin_session');
location.reload();
```

## 8. ความปลอดภัยและข้อจำกัด

- **PIN เป็นการป้องกันระดับเครื่อง ไม่ใช่ authentication ขององค์กร**
  ผู้ที่เข้าถึงเบราว์เซอร์และ DevTools สามารถแก้ไขหรือลบข้อมูลในเครื่องได้
- Web App URL ที่ deploy แบบ “Anyone” สามารถถูกเรียกได้โดยผู้ที่มี URL
  ควรจำกัดการแชร์ลิงก์ และหมุน URL ใหม่หากหลุด
- ข้อมูลในเครื่องผูกกับเบราว์เซอร์/โปรไฟล์นั้น ไม่ซิงค์ข้ามเครื่อง
  ต้องใช้ Google Sheets เป็นแหล่งข้อมูลกลาง
- การล้างข้อมูลในเครื่องขณะเชื่อมต่ออยู่ อาจดึงข้อมูลเดิมจากชีตกลับมา
  (ระบบแจ้งเตือนก่อนยืนยัน)
- ไม่มีระบบแนบไฟล์/รูปภาพ, ไม่มีระบบแจ้งเตือนอีเมล และไม่มี audit log ระดับผู้ใช้
- ไม่มี real-time push จากชีต การอัปเดตใช้การ polling ทุก 60 วินาที
- หากต้องการหลายผู้ใช้แก้ไขพร้อมกัน ควรใช้ Google Sheets เป็นแหล่งหลัก
  และหลีกเลี่ยงการแก้ไขแถวเดียวกันในเวลาเดียวกัน

## 9. การทดสอบที่ทำแล้ว

- ตรวจ syntax JavaScript ทั้ง 5 ไฟล์ (`api.js`, `store.js`, `charts.js`, `app.js`, `sw.js`) ด้วย `node --check`
- ทดสอบ runtime ด้วย jsdom ครอบคลุม 66 checks:
  initial data, tabs, theme, charts, form validation/submit, employee selection,
  search/filter/pagination, CSV (ทั้งตามตัวกรองและ Admin export ทั้งหมด),
  admin PIN/change PIN/logout, edit/delete, settings URL validation,
  XSS escaping, date normalization, offline storage
- ทดสอบคิวออฟไลน์/ซิงค์ 18 checks: กรองพนักงานที่ปิดใช้งาน, create/update/delete
  ขณะออฟไลน์, รวม update เข้ากับ create ที่ยังไม่ซิงค์, flush เมื่อกลับมาออนไลน์
  และล้างข้อมูลในเครื่อง
- ทดสอบโหมดในเครื่องก่อนเชื่อมต่อ 27 checks: สร้าง/แก้ไข/ลบรายการโดยยังไม่มี GAS URL,
  ตรวจรูปแบบ ID และการไม่ชนกัน, ตรวจว่าคิวถูกเก็บและ persist, การลบรายการที่ยัง
  ไม่ซิงค์แล้วคิวถูกยกเลิก, ไม่ส่งข้อมูลตัวอย่างขึ้นชีต, ลงทะเบียน Service Worker,
  ตั้งค่า URL ผ่านหน้า Settings แล้วซิงค์รายการที่ค้างก่อนดึงข้อมูล
  และรายการไม่หาย/ไม่ซ้ำ
- ทดสอบกรณีเพิ่มรายการระหว่างซิงค์ 7 checks ว่ารายการใหม่ไม่ถูกข้อมูลจากชีตทับ
- ทดสอบกรณีชีตส่งรายชื่อพนักงานว่าง 14 checks ว่าล้างรายชื่อเดิม ปิด dropdown
  และกลับมาใช้งานได้เมื่อมีพนักงานอีกครั้ง
- ทดสอบ logic ฝั่ง Apps Script 9 checks: สถานะว่าง = ใช้งาน, สถานะปิดใช้งาน,
  แถวว่าง, การ normalize วันที่, JSON และ update แถวที่ถูกลบแล้วไม่ทำให้คิวค้าง
- ทดสอบ Service Worker 12 checks: pre-cache app shell, ล้าง cache เวอร์ชันเก่า,
  network-first, ไม่อ่านคำขอ POST/cross-origin, fallback asset/navigation ตอนออฟไลน์
- ตรวจ static CSS สำหรับ safe area, overflow และขนาดปุ่มสัมผัส
- ตรวจ layout ด้วย Chromium headless ที่ความกว้าง 320, 360, 390, 430, 768,
  1024 และ 1440px: ไม่มี horizontal scroll ทั้งหน้า, ตารางเลื่อนเฉพาะในกรอบ,
  header actions อย่างน้อย 44px และ modal อยู่ใน viewport
- ตรวจ interaction/visual ด้วย Chromium headless อีก 64 checks ครอบคลุมทุกแท็บ
  และ modal ที่ 320, 390, 768px (ปุ่มแตะขั้นต่ำและ modal fit)
- ตรวจธีมไอคอนและอวตารพนักงาน 10 checks: พนักงานตัวอย่าง 12 คนได้ gradient
  ไม่ซ้ำกัน, สี/ไอคอนตรงกันระหว่างฟอร์ม ตาราง การ์ด แดชบอร์ด และโมดัลแก้ไข,
  ไอคอนตามตำแหน่งทำงาน และไม่มีการล้นจอที่ 320–1280px
- ยังไม่ได้ทดสอบบนอุปกรณ์จริงหรือเบราว์เซอร์จริงผ่าน HTTP ใน environment นี้
  ควรทดสอบอีกครั้งบนมือถือ Android/iOS และเดสก์ท็อปก่อนใช้งานจริง

## 10. Troubleshooting

### เชื่อมต่อไม่ได้ / ขึ้นออฟไลน์
- ตรวจว่า Deploy เป็น Web App และสิทธิ์เป็น **Anyone**
- ตรวจว่า URL ลงท้าย `/exec` (หรือ `/dev` สำหรับทดสอบ)
- เปิด URL ในเบราว์เซอร์แล้วต้องเห็น JSON ไม่ใช่หน้า HTML
- ตรวจว่าได้รัน `setupSystem` ในไฟล์ Sheets ที่ถูกต้อง
- ถ้าเพิ่งแก้ Code.gs ต้อง **Deploy → Manage deployments → Edit → New version**

### กราฟไม่แสดง
- ตรวจว่า `js/vendor/chart.umd.min.js` อยู่ครบ
- เปิด Console ดูว่ามี error จากการโหลดไฟล์หรือไม่
- ถ้าเป็นเครื่องที่บล็อก local file อาจต้องเปิดผ่าน local server

### ฟอนต์ไม่เป็น Prompt
- ตรวจว่าโฟลเดอร์ `fonts/` และ `fonts.css` อยู่ระดับเดียวกับ `index.html`
- เบราว์เซอร์บางตัวบล็อกการโหลด font จาก `file://` ให้ใช้ local server แทน

### ข้อมูลไม่ขึ้นหลังซิงค์
- ตรวจชื่อชีตต้องเป็น `รายชื่อพนักงาน` และ `บันทึกความผิดพลาด`
- ตรวจหัวคอลัมน์ไม่ถูกสลับ (ดู schema ใน README-GAS.md)
- ตรวจว่าแถวข้อมูลเริ่มที่แถว 2 และมี ID ในคอลัมน์แรก
- ดูข้อความ error ในแถบสถานะหรือ Console

### เปิดแล้วยังเห็นหน้าเว็บเวอร์ชันเก่า
- Service Worker ใช้ network-first จึงควรได้ไฟล์ใหม่เมื่อออนไลน์
- ถ้ายังเห็นเวอร์ชันเก่า ให้ปิดแท็บทั้งหมดแล้วเปิดใหม่ หรือกด reload แรง
- ตรวจสอบที่ DevTools → Application → Service Workers แล้วกด **Update** หรือ **Unregister**
- หลังแก้ `sw.js` ให้เปลี่ยน `CACHE_NAME` (เช่น `router-app-shell-v2`) แล้ว deploy ใหม่

### หน้าเว็บเลื่อนซ้ายขวาทั้งหน้า
- ควรเลื่อนได้เฉพาะกรอบตาราง
- ตรวจว่าไม่ได้ใส่ CSS ภายนอกที่กำหนดความกว้างเกิน viewport
- รายงานพร้อมขนาดหน้าจอและเบราว์เซอร์เพื่อตรวจต่อ

## 8. ข้อจำกัดด้านความปลอดภัยก่อนใช้งานจริง

**รุ่นนี้ยังไม่ควรใช้กับข้อมูลพนักงาน/ข้อมูลความผิดพลาดที่เป็นความลับในองค์กรโดยตรง** หาก deploy Apps Script เป็น `Anyone` ตามคู่มือเดิม เพราะ endpoint สามารถถูกเรียกอ่าน/เขียน/ลบข้อมูลได้โดยผู้ที่ทราบ URL และ PIN Admin ฝั่งเว็บไม่ใช่การควบคุมสิทธิ์ฝั่งเซิร์ฟเวอร์

ก่อนใช้กับข้อมูลจริง ต้องเพิ่มการยืนยันตัวตนและตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ (เช่น ระบบ login ที่ตรวจ token ฝั่ง backend หรือ Google Workspace จำกัดผู้ใช้) และทดสอบสิทธิ์อ่าน/เพิ่ม/แก้ไข/ลบแยกตามบทบาท ห้ามถือ URL ลับหรือ PIN ในหน้าเว็บเป็นมาตรการรักษาความปลอดภัย

การปรับปรุงในชุดนี้: การติดตั้งไม่ใส่ข้อมูลสมมติอัตโนมัติอีกต่อไป, เพิ่ม `seedDemoData()` สำหรับชีตทดสอบว่างเท่านั้น และป้องกันข้อความที่อาจถูกตีความเป็นสูตร Google Sheets ในฟิลด์ข้อความที่รับจาก API
